# 🛡️ Introduction to Asset Security (Module 1)

# 📌 Understanding Risk

## Risk

A **risk** is anything that can negatively impact the confidentiality, integrity, or availability of an asset (CIA Triad).

### Risk Formula

```text
Likelihood × Impact = Risk
```

### Risk Helps Organizations:
- Prevent costly disruptions
- Improve systems and processes
- Determine acceptable levels of risk
- Prioritize critical assets

---

# 🔐 Security Risk Planning

Security planning is based on analyzing three major elements:

| Element | Description |
|---|---|
| Assets | Valuable resources owned by an organization |
| Threats | Events or circumstances that could cause harm |
| Vulnerabilities | Weaknesses that threats can exploit |

---

# 🧩 Assets

## Asset

An **asset** is anything considered valuable to an organization.

### Examples
- Buildings
- Equipment
- Data
- Employees
- Intellectual property

---

# ⚠️ Threats

## Threat

Any event or circumstance capable of negatively impacting assets.

---

## Threat Categories

### Intentional Threats
Malicious actions performed deliberately.

#### Example
A hacker exploiting a vulnerable application to steal sensitive information.

---

### Unintentional Threats
Accidental actions that create security risks.

#### Example
An employee allowing an unauthorized person into a restricted area.

---

# 🛠️ Vulnerabilities

## Vulnerability

A weakness that can be exploited by a threat.

---

## Vulnerability Categories

### Technical Vulnerabilities
Weaknesses in hardware or software systems.

#### Example
Misconfigured software exposing sensitive information.

---

### Human Vulnerabilities
Security risks caused by human behavior.

#### Example
An employee losing an access badge.

---

# 📋 Asset Management

## Asset Management

The process of tracking organizational assets and identifying risks affecting them.

---

## Asset Inventory

A catalog of assets requiring protection.

Asset management typically begins with maintaining an accurate inventory.

---

# 🏷️ Asset Classification

## Asset Classification

The process of labeling assets based on sensitivity and importance.

---

## Classification Levels

| Classification | Description |
|---|---|
| Public | Safe to share publicly |
| Internal-Only | Intended only for internal employees or partners |
| Confidential | Restricted to authorized project members |
| Restricted | Highly sensitive information requiring maximum protection |

---

## Public

- Lowest classification level
- Disclosure causes little or no damage

### Examples
- Public website content
- Marketing materials

---

## Internal-Only

- Limited to employees or trusted partners
- Not intended for the public

---

## Confidential

- Access restricted to specific authorized individuals
- Disclosure could significantly impact the organization

---

## Restricted

- Highest sensitivity level
- Requires strict protection

### Examples
- Intellectual property
- Payment information
- Health records

---

# 🔎 Understanding Asset Importance

Organizations should know:

- What assets exist
- Where assets are located
- Who owns the assets
- How important the assets are

---

# ⚠️ Challenges in Asset Classification

## Ownership Challenges

Asset ownership is not always obvious.

### Example
A company-issued laptop used for both work and personal activities.

---

## Multiple Classification Levels

Some assets may contain both public and confidential information.

### Example
A mailed letter containing:
- Public information → recipient name
- Confidential information → home address

---

# 💾 Data

## Data

Information processed, stored, or transmitted by a computer system.

---

# 🔄 States of Data

| State | Description |
|---|---|
| In Use | Data actively being accessed |
| In Transit | Data moving between systems |
| At Rest | Data stored and not actively accessed |

---

# 🛡️ Information Security (InfoSec)

## Information Security

The practice of protecting data in all states from unauthorized access.

---

# ☁️ Cloud Computing Services

## Three Main Cloud Service Models

| Service Model | Description |
|---|---|
| SaaS | Software delivered through the web |
| PaaS | Development platforms hosted online |
| IaaS | Virtualized infrastructure resources |

---

# 💻 Software as a Service (SaaS)

Provides web-based applications managed entirely by the service provider.

### Examples
- Gmail
- Slack
- Zoom

---

# 🏗️ Platform as a Service (PaaS)

Provides online development tools for creating and deploying applications.

### Examples
- Google App Engine
- Heroku
- VMware Cloud Foundry

---

# 🖥️ Infrastructure as a Service (IaaS)

Provides remote access to infrastructure resources such as:
- Servers
- Storage
- Networking

Often more cost-effective than maintaining physical infrastructure.

---

# ☁️ Major Cloud Service Providers

### Common CSPs
- Google Cloud Platform (GCP)
- Microsoft Azure

---

# 🔒 Cloud Security

## Cloud Security

A cybersecurity field focused on protecting:
- Cloud data
- Applications
- Infrastructure

---

## Shared Responsibility Model

Security responsibilities are divided between:
- Cloud provider
- Customer

### Customers Commonly Secure:
- Identity and access management
- Resource configurations
- Data handling

### Providers Commonly Secure:
- Physical infrastructure
- Underlying cloud systems

---

# ⚠️ Cloud Security Challenges

| Challenge | Description |
|---|---|
| Misconfiguration | Improper security settings |
| Cloud-Native Breaches | Attacks exploiting cloud weaknesses |
| Monitoring Access | Difficulty tracking cloud activity |
| Regulatory Compliance | Meeting standards like HIPAA or GDPR |

---

# 🚨 Risk Categories

Common organizational risks include:

- Cyberattacks
- Human error

# 📑 Security Plan Elements

| Element | Purpose |
|---|---|
| Policies | Define security rules |
| Standards | Provide guidance for policies |
| Procedures | Step-by-step security instructions |

---

# 📜 Policy

A set of rules designed to reduce risk and protect information.

Policies serve as the foundation of a security program.

---

# 📚 Standards

References that guide how policies should be implemented.

---

# 🛠️ Procedures

Detailed instructions explaining how to complete security tasks.

---

# ✅ Compliance

## Compliance

The process of following internal standards and external regulations.

---

# ⚖️ Regulations

Rules established by governments or authorities controlling how activities are performed.

---

# 🏛️ NIST Cybersecurity Framework (CSF)

## NIST CSF

A voluntary cybersecurity framework consisting of:
- Standards
- Guidelines
- Best practices

Designed to help organizations manage cybersecurity risk.

---

# 🧩 NIST CSF Components

| Component | Purpose |
|---|---|
| Core | Main cybersecurity functions |
| Tiers | Measure security maturity |
| Profiles | Show current security posture |

---

# 📋 NIST CSF Core Functions

The five primary functions:

1. Identify
2. Protect
3. Detect
4. Respond
5. Recover

---

# 📈 NIST CSF Tiers

| Tier | Description |
|---|---|
| Level 1 | Passive / minimal standards |
| Level 2 | Risk-informed awareness |
| Level 3 | Repeatable and documented |
| Level 4 | Adaptive and optimized |

---

# 🛠️ Implementing the NIST CSF

Organizations commonly:

1. Create a current security profile
2. Perform risk assessments
3. Identify security gaps
4. Develop and implement improvement plans

---

# 🗂️ Risk Register

## Risk Register

A centralized record documenting potential risks to:
- Assets
- Systems
- Data

Frequently used during risk assessments.

---

# 🧠 Key Takeaways

- Risk is determined by both likelihood and impact
- Security planning focuses on assets, threats, and vulnerabilities
- Asset classification helps organizations protect sensitive information
- Data exists in multiple states: in use, in transit, and at rest
- Cloud security responsibilities are shared between providers and customers
- Policies, standards, and procedures form the foundation of security planning
- The NIST Cybersecurity Framework helps organizations manage and improve cybersecurity practices
- Risk registers help track and prioritize organizational risks
